## 一、已诊断问题清单（必须全部修复）

### A. 游戏运行逻辑

1. **结束本轮存在双端竞态**：`finishRound` 只靠本地 `savedRef` 防重。两台设备同时触发（如画题人收到 guess 信号 + 猜题人 1.8s 兜底）时，双方都在本地通过检查、都执行 UPDATE → 轮次被推进两次、`round_results` 重复。必须改为 **数据库条件更新**：`UPDATE ... WHERE id=? AND status='drawing' AND round=?`，并检查返回行数，0 行则视为对方已推进、重新拉取。
2. **提示加时不同步**：`handleGiveHint` 只改本地 `drawEndRef`，对方设备倒计时仍是 0。必须新增 `deadline_at` 字段：选词时写 `now()+60s`，发提示时写 `now()+15s`，双端统一从 DB 行计算剩余时间。
3. **时间到后可能永久卡死**：原流程只能等画题人点「给提示」或「公布答案」，画题人离开/挂机则整局卡死。必须增加**自动超时兜底**：倒计时归零后 30 秒内状态仍为 drawing，则任一端调用 `finishRound('timeout')`（由 A-1 的条件更新保证只生效一次）；画题人发送提示会刷新 `deadline_at` 并取消兜底。
4. **handleJoin 无状态保护**：重复触发可把进行中的对局改回 picking。改为 `WHERE status='waiting'` 条件更新。
5. **再来一局对方无感知**：原 `handleRematch` 只重建本地对局，对方停留在结算页。必须实现 rematch 通知（IM + DB 队列双通道），对方收到后自动切换到新对局；同时保留聊天邀请消息。
6. **候选词闪烁**：`displayWordChoices` 每次渲染随机混入自定义词，自定义词加载完成后候选词会突变。改为按轮次确定性选择（`myWords[(round-1) % len]`）。
7. **轮询期 Alert 轰炸**：`fetchGame` 每 2 秒一次，失败每次都弹窗。只有首次加载（loading 中）才允许弹窗，轮询失败静默。
8. **每 2 秒全量 setGame**：`applyGameSideEffects` 在 picking 阶段每次轮询都 `setStrokes([])` 等空重置，制造无意义重渲染。必须以 `status:round` 为相位键，**只有相位变化才执行重置**；并增加行级相等比较，无变化不 setGame。

### B. 画画同步

9. **乱序丢点**：IM 与 DB 队列双通道之间不保证顺序，`stroke_pts` 先于 `stroke_begin` 到达时被直接丢弃（`rs.si !== m.si`），笔画永久缺段。必须按 `si` 建立暂存区：begin 未到先缓存 pts/end，begin 到达后按序重放。
10. **undo/clear/danmaku/guess 双通道重复执行**：这些信号没有去重 ID，IM 与 DB 各投递一次 → 撤销两笔、弹幕重影、猜词重复。必须为**所有信号**生成 `uid`（发送方生成一次，双通道共用），接收方全局去重。
11. **Realtime 与轮询的 lastId 竞态**：Realtime 把 `queueLastId` 推进后，乱序到达的旧 id 被丢弃且轮询不再拉取。修复策略：Realtime 收到即处理（依赖 uid 去重），`lastId` 只由有序轮询推进。
12. **中途加入同步不可靠**：`sync_request` 与笔画重放只走 IM（12KB 限制下还分多条），跨设备易丢。改为：sync_request 双通道；画题人应答改为**一条 DB 信号 `snapshot`**（jsonb 无 12KB 限制），内含全部已完成笔画的紧凑编码（相对坐标）；猜题人按 round 应用快照并按 round 去重重试。
13. **单点笔画不可见**：`pointsToPath` 对单点只生成 `M x y`，SVG `fill="none"` 下轻点一下图元不可见，但 PNG 光栅化有圆点 → 画布与存图不一致。单点笔画一律渲染 `<Circle>`。

### C. 性能（代码级，禁止引入新重型依赖）

14. **画一个点全屏重渲染**：`addToStroke` 每个 move 事件 `setCurrentStroke` → 整个 Svg（含全部历史笔画 Path）重渲染，且每次 render 对所有历史点执行 `toFixed` 拼路径。修复：
    - 笔画结束时预算好 `d` 存进 stroke 对象；
    - 拆出 `CompletedStrokes = memo(...)`（仅数组引用变化才重渲染）；
    - 当前笔/远程笔单独渲染。
15. **点数据无抽稀**：move 事件高频产生冗余点。距离 < 2px 丢弃，单笔画点数上限 600。
16. **启动时全量模块求值**：`App.js` 顶层 import 全部 Screen（含 pako、react-native-svg、腾讯 IM SDK、image-picker 等），冷启动一次性求值。修复：`lazyScreen(loader)` 高阶组件，首次挂载才 `require` 求值；`wakeUpSupabase`/`initSignal` 改为登录后延迟 require，且 IM 初始化延时至首帧之后（~300ms）。
17. **对局轮询过密**：fetchGame 2s + 信号队列 1.2s。绘制期将 fetchGame 降到 3s（Realtime + 队列双通道已覆盖实时性）。

### D. UI/交互优化（保持设计系统，克制不花哨）

18. 计时改为进度条 + 数字，剩余 ≤10s 变红。
19. 猜题方显示「分类提示 · N 个字」。
20. 工具栏图标改用 Ionicons；颜色点选中态加勾。
21. 等待中的邀请可取消（删除 waiting 对局并回大厅）。
22. 结算页展示每轮明细与比分，保留「再来一局 / 看画廊」。

- 新增 `drawguess_games.deadline_at timestamptz`（可空，向后兼容：空则按 `started_at + 60s` 计算）。
- 修复 `ALTER PUBLICATION supabase_realtime ADD TABLE drawguess_signals;` 重复执行报错：包 `DO $$ ... EXCEPTION WHEN duplicate_object THEN NULL; END $$;`。
- 全部语句保持幂等可重复执行。

## 三、信号协议 v2（`drawguess_signals.data`）

所有信号携带 `uid`；笔画类携带 `si`：

- `stroke_begin {uid, si, c:[r,g,b], w, e, p:[x,y]}`（p 为相对坐标千分位）
- `stroke_pts {uid, si, p:[x1,y1,...]}`
- `stroke_end {uid, si}`
- `undo {uid}` / `clear {uid}`
- `danmaku {uid, text, from}`
- `guess {uid, text, correct, from}`
- `save {uid, round}`
- `update {uid, row}`（整行游戏状态）
- `sync_request {uid, from}`
- `snapshot {uid, round, s:[{c,w,e,p:[...]}]}`
- `rematch {uid, game_id}`

IM 与 DB 队列使用**同一个 uid**，接收端 `processedUid` 去重（容量 1000，超限淘汰最旧 500）。

## 五、验收清单

1. 双端同时触发结束本轮，轮次只推进一次、结果不重复。
2. 画题人发提示后，双方倒计时同步 +15s。
3. 时间到后画题人不操作，30s 后自动按超时结束本轮，双方进入下一轮。
4. 快速连续绘画 + 撤销 + 清空，双端画面完全一致（无双倍撤销、无丢段）。
5. 猜题人中途进入对局，可看到已有全部笔画。
6. 轻点画布出现一个圆点，且保存的 PNG 中也有。
7. 弹幕/猜词无双影。
8. 再来一局：对方自动进入新对局，聊天页出现新邀请。
9. 断网轮询失败不弹窗轰炸；恢复后自动同步。
10. 冷启动首屏（登录后时光胶囊）渲染前，不加载五子棋/你画我猜/pako/svg 模块（打点验证 module 求值时机）。
11. 其余既有功能（聊天/打卡/五子棋/时光胶囊/愿望清单/纪念日/旅行日记）无回归。
